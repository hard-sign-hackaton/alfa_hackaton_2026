# Связи новостей с компаниями

Таблица `news_company_links` в общем PostgreSQL хранит уникальные пары
`(news_id, company_id)`. Оба идентификатора имеют внешние ключи на исходные таблицы.
Миграции: `0006_news_company_links` и `0007_link_source_invalidation`,
применяются сервисом `news-db-init`. Изменения платежных данных и даты
публикации также сбрасывают актуальность прежних разборов.

В строке сохраняются:

- способ и основания подбора, поисковый балл, темы, признак активной связи;
- важность `high / medium / low`, объяснение, точные основания и статус оценки;
- состояние полного разбора, его результат и время подготовки;
- хеши новости и профиля компании, даты обновления.

Поисковый балл используется для порядка кандидатов, а не как вероятность влияния.
Связь по сходству текста не является подтверждённым влиянием на компанию.

При запуске `web` существующие подборки и совместимые разборы переносятся в БД.
Повторная загрузка не создаёт дубликатов и не заменяет более новый разбор старым.
После этого лента и чтение связей в обоих направлениях используют PostgreSQL.
Файлы результатов остаются экспортом и резервным набором для режима без базы.

Фоновая обработка запускается при старте и каждые `LINKS_SYNC_SECONDS` (300 по
умолчанию). Для компаний подбираются новости с учётом деятельности и агрегатов
платежей. Неделовые публикации отфильтровываются. Для каждой активной пары без
оценки выполняется отдельный короткий вызов Gemma. Полное исследование для этого
не требуется. Повторный проход переиспользует готовые оценки. После трёх неудачных
попыток сохраняется `failed`, искусственная оценка не подставляется.

Оценка важности проверяет идентификаторы оснований и подставляет точные цитаты
из новости и профиля. Это предварительная качественная оценка; полный разбор
может её уточнить. Общая лента содержит также новости, для которых связь с
выбранной компанией ещё не установлена, поэтому персональной оценки у них нет.

Полный разбор сохраняется в той же строке. Новая версия новости или компании
делает старую строку недоступной в актуальной выдаче. Повторный подбор сбрасывает
устаревшие оценки; запоздавший ответ модели не может перезаписать новую версию.

Доступ:

- `analysis_news_reader` читает исходные данные и не получает права записи;
- `analysis_links_writer` читает новости/компании и может записывать только
  таблицу связей. Пароль `LINKS_WRITER_PASSWORD` необязателен; при отсутствии
  используется `NEWS_READER_PASSWORD`. Модели не получают строк подключения.

API:

- `GET /api/news-companies?news_id=...` — сохранённые связи новости с компаниями;
- `POST /api/matches` с `company_id` и `news_id` — обратный подбор по эмбеддингам,
  сохранение кандидатов и оценка их важности; возвращает фоновое задание;
- `GET /api/jobs/{id}` — состояние задания;
- `GET /api/feed?company_id=...` — лента и оценки из таблицы связей;
- `POST /api/analysis` — полный разбор с сохранением в таблицу.

Пользователь открывает разбор для компании, выбранной в верхней панели.
Обратный подбор доступен через API и CLI для обслуживания связей;
список других компаний не выводится в карточке новости.

Команды внутри контейнера с `LINKS_DATABASE_URL`, `NEWS_DATABASE_URL` и ключом:

```sh
python -m app.modules.links stats
python -m app.modules.links sync
python -m app.modules.links match-news --news-id NEWS_ID
```

Интеграционные проверки разрешены только при `LINKS_TEST_DATABASE_URL`, указывающем
на отдельную базу с суффиксом `_test`:

```sh
python -m unittest discover -s tests/links -v
```
