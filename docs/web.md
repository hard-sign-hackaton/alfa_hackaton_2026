# Веб-приложение

Запуск из корня проекта:

```powershell
docker compose --profile web up --build -d web
```

Интерфейс: http://127.0.0.1:8080. Остановка: `docker compose stop web`.
Нужны обычные переменные `.env` для PostgreSQL и моделей. `NEWS_DATABASE_NAME`
выбирает базу с новостями, компаниями и банковской аналитикой. На первом запуске
сервис `data-init` автоматически восстанавливает SQL-набор из `database/seeds`:
новости, компании, банковские материалы, эмбеддинги, связи, оценки и готовые
разборы. Повторный запуск сохраняет существующие данные. Подробности:
[startup-data.md](startup-data.md). Дополнительный импорт выполняется командами модулей.

React и Vite находятся в `frontend/`. Кнопки и переменные оформления —
`@alfalab/core-components-button` и `@alfalab/core-components-vars`.
Сборка фиксируется `pnpm-lock.yaml`; используется pnpm 11.

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm run check
pnpm run build
```

Сервер: `python -m app.web`, порт `WEB_PORT` (8080 по умолчанию),
`WEB_HOST` (127.0.0.1), статика `frontend/dist`.
Для разработки Vite проксирует `/api` на 127.0.0.1:8080.

`GET /api/bootstrap` возвращает компании, каталог документов и состояние данных.
`GET /api/feed?company_id=...` — публикации, сохранённый подбор и готовые сводки.
`GET /api/analysis?company_id=...&news_id=...` — полный разбор и материалы.
`GET /api/bank-sources` — фрагменты банка из готовых разборов.
`POST /api/analysis` принимает `company_id` и `news_id`, запускает существующий
LangChain-пайплайн. `GET /api/jobs/{id}` возвращает состояние и этап.
`POST /api/chat` дополнительно принимает `question` и необязательный
`conversation_id`. Контекст и история ответов формируются сервером.
На каждом вопросе чат заново ищет новости и банковские материалы в базе.
Модель может уточнять поиск через инструменты чтения. Найденные фрагменты,
цитаты и ограничения возвращаются вместе с ответом. Можно обсуждать другую
новость, сохраняя выбранную компанию и исходную карточку контекстом диалога.
Подробнее: [chat-retrieval.md](chat-retrieval.md).

Обработка моделей выполняется в одном рабочем потоке с очередью до двух запросов.
Повторный запуск той же пары во время обработки возвращает существующее задание.
Связи, оценки важности и новые разборы сохраняются в PostgreSQL. Экспорт
разборов дополнительно записывается атомарно в `WEB_RUNTIME_DIR` (локально
`local_runtime/web`, в контейнере постоянный том). Диалоги живут до перезапуска.
Ключи и строки подключения не передаются браузеру. Запись в исходные таблицы
из интерфейса отсутствует. Приложение предназначено для локального запуска;
перед публичным размещением нужна авторизация и разграничение компаний.

При недоступной базе интерфейс явно показывает сохранённый набор из
`research/evaluation`. Новые разборы тогда отключены. В режиме без базы используется сохранённый персональный подбор на 22.10.2026.
При подключённой базе связи обновляются автоматически; важность оценивается
отдельно от полного исследования. У новости есть вкладка «Компании» для
обратного поиска. Хранение и API описаны в [news-company-links.md](news-company-links.md).
Важность показывается только из готовой персональной классификации.
Неоценённые новости не получают искусственную метку важности.
Каталог банка фильтруется по названиям и тегам; поиск контекста по фрагментам
выполняется внутри агента при подготовке разбора.

Проверка сервера: `python -m unittest discover -s tests/web -v`.
