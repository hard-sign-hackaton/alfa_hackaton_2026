# Сопоставление и исследование новостей

Компания ищет новости по коротким отраслевым запросам. Ключевые слова и E5 объединяются по рангам; для выдачи нужен лексический сигнал. Отдельно рассматриваются ключевая ставка и отрасли контрагентов. География регистрации не считается географией продаж. Доли контрагентов не определяют, кто покупатель, а кто поставщик.

Обратный поиск использует эмбеддинги компаний из `app.modules.companies`. Новость кодируется E5 с префиксом `query:`, профиль компании — `passage:`. Совпадение модели, revision, нормализации и размерности проверяется; правила подготовки и profile_id у компаний и новостей различаются. Сходство выбирает кандидатов, а не определяет влияние или важность.

Затем агент получает конкретную пару, читает профиль и готовые платежные агрегаты, ищет дополнительные новости и формирует разбор. Gemma классифицирует публикацию, Qwen извлекает событие, DeepSeek собирает контекст через инструменты чтения и анализирует влияние. Модель выбирает ID фрагментов; точные цитаты подставляет код. Summary строится из принятых claims. Это исключает новые сведения в summary, но смысловую обоснованность самих claims всё ещё нужно оценивать.

## Запуск в Docker

Настройки доступа берутся из `.env`. Для экспериментов задайте `NEWS_DATABASE_NAME` отдельной исследовательской базы. Перед импортом база должна существовать. Дамп и исходные материалы не добавляются в Git.

```powershell
docker compose build ai-agent-semantic news-db-init news
docker compose run --rm news-db-init
docker compose run --rm companies import
docker compose run --rm companies embed --revision 614241f622f53c4eeff9890bdc4f31cfecc418b3
```

`companies` использует образ `news`. Модель E5 загружается один раз в том `news-models`. Агент читает таблицы ролью `analysis_news_reader`; импорт и расчёт векторов выполняются отдельными командами с правами записи.

Компания → новости, без вызовов LLM:

```powershell
docker compose run --rm --no-deps --entrypoint python ai-agent-semantic match_company.py --company-id U_128194 --output /output/company-matches.json
```

Новость → компании, без вызовов LLM:

```powershell
docker compose run --rm --no-deps --entrypoint python ai-agent-semantic match_companies.py --news-id NEWS_ID --output /output/news-matches.json
```

Чтобы учесть уже рассчитанные темы публикации, добавьте `--preparation /output/путь/preparation.json` с объектом NewsPreparation. ID публикации и дословность цитат классификации проверяются. Из расширенной выборки E5 сначала выбираются компании с совпадением темы и ОКВЭД, затем учитывается исходное сходство. Без подготовки используется только E5; его выдача может быть шумной. Тема `not_business` исключает выдачу компаний. Новых вызовов моделей эта команда не делает.

Полный разбор пары с вызовами моделей:

```powershell
docker compose run --rm --no-deps ai-agent-semantic --company-id U_128194 --news-id NEWS_ID --output /output/pair-analysis
```

У всех трёх команд есть `--as-of` с датой и часовым поясом. Публикация должна быть опубликована до среза, а компания — импортирована до него. Хранятся текущие снимки компаний, без истории версий. Повторный импорт неизменённого снимка не сдвигает его доступность. Период платежей неизвестен: динамика, сезонность и текущая экспозиция из этих агрегатов не выводятся.

## Проверка результата

Сравнение на замороженном корпусе: `research/evaluation/2026-10-22-improved/report.html`. Исходный прогон сохранён в соседней папке `2026-10-22`. Это диагностика поведения на 153 новостях и 12 компаниях, а не измеренная точность продукта. Ранее модельно оценённые пары не являются независимой разметкой.

Повторить фазы на подготовленной исследовательской базе:

```powershell
python scripts/run_pipeline_comparison.py classify --database alfa_research_20261022
python scripts/run_pipeline_comparison.py retrieval --database alfa_research_20261022
python scripts/run_pipeline_comparison.py analyze --database alfa_research_20261022
python scripts/run_pipeline_comparison.py report --database alfa_research_20261022
```

Скрипт сохраняет успешные ответы и повторяет только незавершённые. Сетевые повторы ограничены; ошибки авторизации повторно не отправляются. Расход записывается из usage шлюза, стоимость ответов без usage неизвестна.

Проверка общих таблиц и обратного поиска после импорта выполняется отдельно: `research/ai/check_company_integration.py --output /output/shared-company-check.json` внутри образа агента. Она проверяет точный состав исследовательского набора, SELECT-права, временные срезы, совместимость профилей E5 и три примера поиска компаний.

Банковские документы в исследовательскую БД пока не загружены. Наличие модуля банковской аналитики не означает, что этот источник уже участвует в разборе.
