# Поиск в диалоге

`POST /api/chat` выполняет RAG на каждом вопросе, включая последующие сообщения
с тем же `conversation_id`. Не требуется заново готовить полный разбор.

Сначала выполняются два поиска по тексту вопроса: новости и банковские материалы,
до двух фрагментов каждого типа. Используется существующий PostgreSQL-поиск:
E5 и полнотекстовый поиск в режиме `hybrid`, даты ограничены временем текущего
вопроса. Поэтому доступны публикации, появившиеся после первоначального разбора.

DeepSeek получает вопрос, последние вопросы и ответы, исходную новость, профиль
компании и результаты первого поиска. Он может вызывать `search_news`,
`search_bank_analytics`, `get_company_profile`, `get_company_metrics`. Сервер
выполняет запросы только на чтение для выбранной компании. Можно уточнить тему
и поиск, если первый запрос оказался слишком общим или вопрос содержит местоимения.

Лимиты: три раунда планирования, шесть вызовов инструментов вместе с двумя
начальными, десять новых источников и 36 000 символов новых фрагментов на вопрос.
Повторные запросы кешируются внутри шага; недоступный инструмент не запрашивается
повторно. Ошибка поиска не трактуется как отсутствие события или риска.

GLM формирует ответ по найденным данным и исходному контексту. Полная подготовка
новости (классификация/извлечение/важность) заново не запускается. При недоступном
планировщике остаются результаты первичного поиска, а ограничение явно возвращается.
Без новых результатов используются доступные основания разбора и предыдущих ответов.

Реестр источников принадлежит серверу. Цитаты проверяются на точное вхождение
в соответствующий фрагмент; ответы с неизвестным источником отклоняются.
Новые источники имеют приоритет. История дополняется только теми предыдущими
ответами, чьи цитаты полностью проверяются в текущем реестре. Если источник
изменился или контекст не помещается, такой ответ исключается с ограничением.
Общий контекст — до 16 источников и 60 000 символов извлечённых фрагментов.
Проверка цитат не является независимой оценкой правильности рассуждений модели.

Задание `GET /api/jobs/{id}` возвращает `answer` (контракт Insight),
`retrieved_sources` (реестр данного ответа), `retrieval` (время, статус,
след инструментов, новые идентификаторы и ограничения). Интерфейс показывает
цитаты из реестра конкретного ответа и раскрываемые материалы поиска.

Исходный разбор и его сохранённые источники остаются неизменными. Дополнения
живут только в серверном диалоге; другой диалог их не получает. Компания
и исходная карточка не меняются от вопроса о другой публичной новости.
Сеансы по-прежнему ограничены десятью ответами и сбрасываются при перезапуске.

Проверка: `python -m unittest test_chat_agent -v` из `research/ai` и
`python -m unittest discover -s tests/web -v` из корня. Ключ модели требуется
только для живого прогона; автоматические проверки используют тестовые клиенты.
