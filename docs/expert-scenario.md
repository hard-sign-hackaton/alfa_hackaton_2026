# Общий сценарий для эксперта

После оценки каждой компании важность сразу передается в состояние сценария.
Следующий опрос ленты обновляет положение карточки по общей сортировке, не дожидаясь полного разбора.

«Моя лента» → «Сценарий для эксперта» → «Запустить сценарий».
Сеанс общий для всех компаний из базы. Переключение компании или отраслевого
профиля меняет видимую ленту, но не останавливает обработку и не создаёт новый поток.
Повторное подключение к активному сеансу возвращает тот же идентификатор.
«Повторить общий сценарий» перезапускает весь поток, «Завершить общий сценарий»
останавливает его для всех профилей.

Для каждой компании формируются два вымышленных события: ограничение основных
операций и изменение цены вспомогательного сервиса по действующему договору.
В текстах используются настоящие идентификатор, ОКВЭД и регион регистрации из
профиля. Это входные тексты, они не содержат заданной важности, готовых выводов
или требуемого ответа модели. Дополнительно поступают культурная контрольная
новость и повтор первой публикации. Для 12 компаний это 25 уникальных новостей
и один повтор, поступающих с 2-й по 27-ю секунду. Это сроки поступления, а не
обещание готовности. Важность и результаты могут отличаться между прогонами.

Нужны ключ моделей, PostgreSQL, подготовленные профили эмбеддингов и E5.
Обработка ограничена двумя рабочими потоками; ручной разбор и чат используют
отдельную очередь. Каждый этап выполняется реально:

1. NewsRepository.save_deduplicated сохраняет публикацию и проверяет дубль.
2. NewsEmbeddingService рассчитывает и сохраняет вектор публикации.
3. LinkService классифицирует её, подбирает компании и оценивает важность.
   Явное упоминание известного идентификатора компании ограничивает кандидатов
   этой компанией; вектор и его сходство при этом рассчитываются обычным способом.
4. DatabaseResearchAgent выполняет полный разбор, поиск новостей и банковских
   материалов, проверку цитат и краткую сводку.
5. LinkRepository сохраняет связи, важность и полный результат в PostgreSQL.

Высокая или средняя важность не прописываются в сценарии. Их наличие проверяется
по фактическим ответам моделей, включая итоговую оценку после полного разбора.
Ошибка или отсутствие данных остаются видимыми. Тестовый источник не является
подтверждением реального происшествия; модели получают соответствующую пометку.

Новостям назначаются ID demo:<сеанс>:<номер>, источникам —
expert-demo:<сеанс>:<компания>. Разные адресаты не смешиваются при дедупликации,
повтор сравнивается с исходной публикацией своего адресата. Обычная лента,
RAG и экспорт SQL исключают тестовые записи. Адреса expert-demo.invalid служат
техническими идентификаторами. Остановка не удаляет результаты проверки из БД.

Compose настраивает отдельное подключение EXPERT_DATABASE_URL для роли
analysis_demo_writer. Разрешены SELECT/INSERT/UPDATE только на news_sources,
news_articles, news_embedding_profiles, news_embeddings и USAGE/SELECT на
news_embeddings_id_seq. Роль создаёт news-db-init; пароль EXPERT_WRITER_PASSWORD
по умолчанию равен LINKS_WRITER_PASSWORD. Модели используют только чтение.

EXPERT_MATCH_LIMIT ограничивает обычных семантических кандидатов от 1 до 5.
В ленте показываются предназначенные текущей компании публикации и фактически
найденные для неё связи. Анализ другой компании не подставляется при переключении.
После готовности доступны чат и оценки с is_demo=true. Срок жизни сеанса — час.

Состояние общего сеанса сохраняется атомарно в WEB_RUNTIME_DIR. После перезапуска
готовые разборы восстанавливаются, незавершённые задачи продолжаются. Кнопка
«Повторить ошибки» повторяет только неудачные задачи с теми же публикациями.
Уже сохранённый разбор с актуальными хешами источников используется повторно.
E5 сначала загружается из кэша закреплённой ревизии; скачивание нужно только
при отсутствии файлов модели.

Первой в очереди идёт компания, из профиля которой запущен общий поток;
остальные компании обрабатываются в том же сеансе.

Качественная связь события и возможность рассчитать денежный эффект оцениваются
отдельно. supported означает обоснованный условный канал по цитатам новости и
профиля. Неизвестная величина потерь сама по себе не отменяет такой канал.
Банковский обзор даёт дополнительный контекст и не обязан подтверждать прямое
предписание или изменение договора. Проверки цитат и критерии уровней важности
при этом сохраняются. Вымышленное событие не становится реальным фактом.
