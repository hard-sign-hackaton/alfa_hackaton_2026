# Сценарий для эксперта

«Моя лента» → «Сценарий для эксперта» → «Запустить сценарий».
Моделируется только поступление трёх вымышленных публикаций и одного повтора
на 2-й, 10-й, 18-й и 26-й секундах. Это сроки поступления, а не обещание готовности.
Нужны ключ моделей, доступная PostgreSQL, подготовленные профили эмбеддингов
и локальная модель E5. Без них сервер возвращает ошибку, шаблонных результатов нет.

Обработка выполняется последовательно через рабочие сервисы:

1. NewsRepository.save_deduplicated: сохранение и отсечение повтора в БД.
2. NewsEmbeddingService: расчёт и сохранение настоящего эмбеддинга публикации.
3. LinkService.match_news: классификация моделью, подбор компаний по эмбеддингам
   из всей базы и отдельная оценка важности для каждой связи.
4. DatabaseResearchAgent: полный разбор для каждой подобранной компании,
   включая поиск банковских материалов, проверку цитат и краткую сводку.
5. LinkRepository: сохранение связей, важности и полного результата в PostgreSQL.

По умолчанию выбирается до пяти компаний; EXPERT_MATCH_LIMIT ограничивает
количество от 1 до 5 для контролируемого прогона. Компания пользователя не
добавляется принудительно. Если она не подобрана, интерфейс явно сообщает об этом.
Каждый этап показывается после фактического запуска/завершения соответствующей
операции. Ошибка модели или БД видна как ошибка; таймер не выдаёт статус «готово».
Карточки обновляются раз в 1,2 секунды, обработка может занимать несколько минут.

Публикации помечены «ТЕСТ», источник expert-demo:<сеанс>, ID demo:<сеанс>:<номер>.
При сохранении выполняется обычная дедупликация в пределах сеанса. Старые
тестовые публикации не влияют на дедупликацию новых сеансов и обычного сборщика.
Лента, обычный подбор, RAG и экспорт SQL исключают тестовые записи.
Адреса expert-demo.invalid служат идентификаторами, внешнего источника у них нет.

Compose настраивает EXPERT_DATABASE_URL: отдельную роль analysis_demo_writer
в той же базе, с SELECT/INSERT/UPDATE только на news_sources, news_articles,
news_embedding_profiles, news_embeddings и USAGE/SELECT на news_embeddings_id_seq.
Права чтения агента остаются прежними; модели не получают доступ к записи.
Роль и разрешённые права создаёт news-db-init. Пароль задаётся через
EXPERT_WRITER_PASSWORD, по умолчанию используется LINKS_WRITER_PASSWORD.
Модели не получают это подключение: оно используется только сервером при приёме.

Остановка отменяет ещё не начатые работы и дальнейшие этапы текущей обработки.
Уже выполняющийся запрос модели может завершиться. Сохранённые тестовые записи
остаются в БД для проверки; в обычной ленте они не появляются. Повторный запуск
создаёт новый сеанс. Срок жизни сеанса — час, максимум 16 сеансов, один активный
сценарий для каждой компании. Чат и оценки доступны после готовности разбора;
оценки сохраняются с is_demo=true отдельно от обычных оценок.
