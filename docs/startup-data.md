# Стартовые данные

```powershell
docker compose --profile web up --build -d web
```

Достаточно заполнить пароли в `.env` по `.env.example`. Схема основной базы
создаётся миграциями, роли получают ограниченные права. Затем `data-init`
восстанавливает данные, и запускается веб-приложение на http://127.0.0.1:8080.
Исходный `chunks.jsonl`, PDF и бинарный `.dump` для этого не нужны.

SQL-файлы в `database/seeds`:

| Файл | Данные |
| --- | --- |
| `01_news.sql` | 153 новости, источники, профили и 153 эмбеддинга |
| `02_companies.sql` | 12 компаний, группы, платёжные агрегаты, профили и 12 эмбеддингов |
| `03_bank.sql` | 9 банковских документов, 138 фрагментов, профили и 138 эмбеддингов |
| `04_links.sql` | 27 связей с оценками важности, 27 полных разборов и коротких сводок |
| `05_agent.sql` | Совместимость со старым агентом: 2 демонстрационных профиля, 8 новостей и 2 пары; банковских материалов в этой базе нет |

Это сохранённый набор данных на 24.10.2026. Полные разборы подготовлены для всех активных релевантных связей; индивидуальные ограничения результатов сохранены. Ограничения и незавершённые
выводы в результатах сохранены. Даты публикаций и импорта остаются исходными.
Сеансы чата и секреты в дампы не входят. Полные веса E5 не входят в SQL:
при первом семантическом поиске модель скачивается в постоянный том `news-models`.
Готовая лента, оценки и разборы доступны без вызовов LLM; для новых разборов
и диалогов нужен `LLM_API_KEY`. Фоновое обновление при наличии ключа может
обращаться к моделям.

Восстановление выполняется в одной транзакции на каждую базу. До записи
проверяются SHA-256 всех файлов по `manifest.json`, после — количество строк.
Порядок файлов учитывает внешние ключи; значения последовательностей сохранены.
Роли, пароли, миграции и настройки сервера в SQL-дампы не включены.

Если в базе уже есть данные, основной набор пропускается. Если при этом все
таблицы банковских материалов пусты, отдельно загружается `03_bank.sql`:
новости, профили и результаты не перезаписываются. Частично заполненный
банковский набор сохраняется без изменений. Результат виден в
`docker compose logs data-init`. Дополнительно загрузчик дополняет готовые
разборы для совпадающих новостей и компаний из `04_links.sql`, даже если БД
уже заполнена. Сравниваются полные исходные записи (включая платежи), кроме
времени импорта/сбора. Изменённые профили, новые результаты и выполняющиеся
разборы не перезаписываются; исходные записи не меняются. Это обеспечивает
готовые разборы после переключения профиля на существующем томе.
Старые базовые данные по-прежнему не заменяются. Чтобы отключить стартовые данные:
`STARTUP_DATA_ENABLED=false`. Не удаляйте существующие тома для обновления набора.

Порядок предрасчёта: [precomputed-analysis.md](precomputed-analysis.md).

Обновить снимок из работающих контейнеров (без Python-зависимостей):

```powershell
python scripts/export_startup_data.py --news-database alfa_news
```

Укажите фактическое имя основной базы. Каждый экспорт базы выполняется одним
`pg_dump`, поэтому её таблицы читаются в согласованном снимке. Файлы содержат
только данные (`INSERT`, восстановление последовательностей), схему создаёт
текущая версия приложения. Для отдельного ручного восстановления сначала
создайте схему и выполните файлы 01–04 в указанном порядке в основной базе,
а 05 — в старой базе агента. SQL запускается внутри транзакции
(`psql --single-transaction -v ON_ERROR_STOP=1 -f ...`). Штатный `data-init` добавляет проверку пустоты,
контрольные суммы, транзакцию и проверку количества строк.
