# Оценки разборов

В конце готового разбора доступны «Полезно» и «Не полезно». Повторное нажатие
убирает оценку; выбор другой кнопки меняет её. Интерфейс подтверждает сохранение
после ответа PostgreSQL, при ошибке предлагает повторить запрос.

Таблица `analysis_feedback` создаётся миграцией `0008_analysis_feedback`.
Оценка содержит компанию, новость, хеш версии анализа, анонимный идентификатор
браузера, `vote` (1 или -1), `is_demo`, идентификатор тестового сценария,
время анализа и даты создания/изменения. Имена, контакты и тексты вопросов
в эту таблицу не записываются.
Анонимный идентификатор хранится в HttpOnly/SameSite-cookie; один браузер может
оставить одну оценку одной версии разбора. При повторном расчёте новая версия
получает отдельные оценки, старые сохраняются. Смена компании не переносит оценку.

Обычный запуск Compose выполняет миграцию и даёт роли приложения доступ к
таблице отзывов. Исходные новости и профили эта роль по-прежнему не изменяет.
Отзывы пользователей не включаются в стартовые SQL-дампы.

Для оценки полезности: доля положительных = положительные / все оставленные
оценки. При отсутствии оценок показатель не определён. Тестовые отзывы
учитываются отдельно от обычных; повторные нажатия не увеличивают знаменатель.
Это пользовательская оценка полезности; корректность фактов проверяется отдельно.

```sql
SELECT is_demo, count(*) AS ratings,
       count(*) FILTER (WHERE vote=1) AS positive,
       count(*) FILTER (WHERE vote=-1) AS negative,
       count(*) FILTER (WHERE vote=1)::numeric / NULLIF(count(*),0) AS positive_share
FROM analysis_feedback
GROUP BY is_demo;
```
