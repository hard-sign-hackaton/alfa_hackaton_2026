## Извлечение данных из аналитических материалов

Проводится с помощью скрипта `extract_pdf.py`.
Он преобразует PDF в Markdown, повторно распознаёт таблицы и сохраняет структуру документа.
В итоге данные сохраняются в формате `JSON`: текст (`markdown`), таблицы (`tables`), заголовки (`title`, `subtitle`, `headings`) и предупреждения (`warnings`).

```sh
python research/bank/extract_pdf.py document.pdf document.json
python research/bank/extract_pdf.py document.pdf document.json --no-cell-ocr
python research/bank/extract_pdf.py document.pdf document.json --keep-last-page
python research/bank/extract_pdf.py document.pdf document.json --no-page-markers
python research/bank/extract_pdf.py ../alfa_hakaton_2026_data/ALFA-7M26.pdf out.json --source-root ../alfa_hakaton_2026_data
```

Текст и разметка извлекаются Docling с OCR EasyOCR (`ru`, `en`). Ячейки таблиц дополнительно распознаются tesseract (`rus+eng`), результат заменяет текст ячейки, если он непустой; при отсутствии tesseract или ошибке OCR сохраняется исходный текстовый слой. Флаг `--no-cell-ocr` отключает повторный OCR ячеек.

По умолчанию между страницами Markdown вставляется маркер `<!-- page break -->`. Благодаря этому `prepare_chunks.py` проставляет страницы не только табличным, но и текстовым чанкам. Флаг `--no-page-markers` отключает маркеры, если нужен прежний формат.

Последняя страница PDF по умолчанию не распознаётся: в этих материалах на ней только дисклеймер, а распознавание стоит времени. Номера страниц в результатах остаются исходными (`tables[].source.page`, `headings[].page`, `pages` чанков). Флаг `--keep-last-page` включает последнюю страницу. В JSON пишутся `page_count`, `pages_processed` (список реально обработанных страниц) и `skipped_pages`.

В JSON также сохраняются `source_name`, `source_sha256`, `source_bytes` и `extractor` (версии Docling и OCR). По умолчанию `source_pdf` записывается в том виде, в каком путь передан аргументом, без `resolve()`. Флаг `--source-root` сохраняет путь относительно указанного каталога, чтобы JSON не зависел от машины.

Графики и другие изображения не анализируются. Попытки распознавать графики vision-моделью оказались ненадёжными, поэтому данные с них в JSON не попадают; изображения страниц используются только для OCR таблиц.

## Подготовка к эмбеддингам

`prepare_chunks.py` разбивает извлечённые материалы на смысловые блоки: один PDF может покрывать несколько слабо связанных тем, а эмбеддинг нужен на уровне темы, а не всего файла.

```sh
python research/bank/prepare_chunks.py ../alfa_hakaton_2026_data/extracted
python research/bank/prepare_chunks.py ../alfa_hakaton_2026_data/extracted --max-tokens 384
python research/bank/prepare_chunks.py ../alfa_hakaton_2026_data/extracted --max-tokens 384 --ignore-heading 'Центр макроэкономического анализа'
python research/bank/prepare_chunks.py ../alfa_hakaton_2026_data/extracted -o chunks.jsonl --json
```

По умолчанию результат пишется в `<входной каталог>/chunks.jsonl` (один JSON-объект на строку). После обновления `extract_pdf.py` старый `chunks.jsonl` нужно пересобрать: страницы текстовых чанков появляются только из маркеров `<!-- page break -->`.

Как формируются блоки:

1. Заголовки Markdown задают разделы; путь заголовков попадает в `section_path` и в `embedding_text`. Первый заголовок считается названием документа, а не разделом и не попадает в `section_path`.
2. Повторяющиеся колонтитулы (например, «Центр макроэкономического анализа») исключаются флагом `--ignore-heading`; флаг можно указывать несколько раз.
3. Короткие заголовки-подписи вида `Новость:` / `Компания:` / `Наше мнение:` считаются частью текста, а не новым разделом.
4. Абзацы, списки и таблицы остаются внутри своего раздела; блок длиннее бюджета делится по границам предложений, а при отсутствии границ (OCR-«простыни») — по словам с перекрытием.
5. Длинные таблицы делятся по строкам с повтором шапки; `tables[].part`/`parts` показывают часть.
6. Повторяющиеся футеры, дисклеймеры и юридические разделы отбрасываются (`--keep-disclaimers` отключает это). Полные дубликаты текста внутри документа удаляются.
7. Строки-подписи источников (`Источники: ...`) и мусор короче порога отбрасываются.

Бюджет:

- по умолчанию — 1000 символов (`--max-chars`), зависимостей не требует;
- с `--max-tokens 384` бюджет считается токенайзером `intfloat/multilingual-e5-small` (нужен `transformers`), что гарантирует попадание в лимит E5 в 512 токенов. Проверка на корпусе: максимум 413 токенов вместе с префиксом `passage: `.

Поля чанка: `id`, `doc_id`, `doc_title`, `source_pdf`, `source_name`, `section_path`, `kind` (`text`/`table`/`mixed`), `text` (тело), `embedding_text` (тело с контекстом документа и раздела), `chars`, `size` (в единицах бюджета), `tables`, `pages`, `content_hash`, `oversized`. `pages` заполняется из маркеров `<!-- page break -->`; для таблиц страница дополнительно берётся из `tables[].source.page`. Если извлечение выполнено без `--no-page-markers`, страницы есть у всех чанков.

Префикс `passage: ` добавляет провайдер эмбеддингов (`app/shared/embeddings/e5.py`), в `embedding_text` его нет.

## Загрузка в PostgreSQL

Канонические метаданные документов (даты, типы, теги) задаются в `research/bank/manifest.json`. Импорт и поиск описаны в [docs/analytics-storage.md](../../docs/analytics-storage.md):

```sh
python -m app analytics import \
  --extracted ../alfa_hakaton_2026_data/extracted \
  --manifest research/bank/manifest.json \
  --source-root ../alfa_hakaton_2026_data
```
