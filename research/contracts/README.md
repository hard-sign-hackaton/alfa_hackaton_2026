# U01 · JSON-контракты v0.1.0

Для стыковки текущего AI-модуля, классификатора, банковского поиска и UX см. [T01: границы компонентов](t01/README.md). AI-формат и UX-формат разделены явно; существующие U01-схемы не изменены. Новые форматы сборки не обязывают AI возвращать все поля интерфейса.

Черновые контракты для обмена данными между обработкой данных, аналитикой и интерфейсом. Описания полей из [UX-спецификации](../ux/README.md) преобразованы в JSON Schema Draft 2020-12. Выбор backend, транспорта, БД и алгоритмов этим не фиксируется. Все примеры вымышлены; обзоры банка в них не выражают реальную позицию Альфа-Банка.

| Схема | Объект | Пример |
|---|---|---|
| `company-profile.schema.json` | Профиль компании, версия, признаки и происхождение | `examples/company-profile.json` |
| `news-event.schema.json` | Событие, текст, источники и факты | `examples/news-event.json` |
| `feed-card.schema.json` | Компактная персональная карточка ленты | `examples/feed-card.json` |
| `insight.schema.json` | Подробный разбор, позиция банка, расчёт и журнал действий | `examples/insight.json` |
| `chat-context.schema.json` | Диалог и снимок контекста компании, события и разбора | `examples/chat-context.json` |
| `common.schema.json` | Общие типы: источник, признак, утверждение, расчёт, шаг проверки | Через `$ref` в остальных схемах |

`examples/insight-partial.json` показывает отсутствие позиции банка и численной оценки. `null` означает неизвестное/неприменимое значение, а не ноль или отсутствие риска. В `source.url` допускается `null` для внутренних материалов и демо-сценариев; тогда используется `locator`. Неизвестная дата публикации остаётся `null`, дата загрузки её не подменяет.

## Как использовать

1. Backend подготавливает `CompanyProfile` и `NewsEvent` с происхождением данных. `company_id` связывается с `SYNTHETIC_U` после проверки исходного датасета; юридическое имя из обезличенного ID не восстанавливается.
2. Результат анализа — `Insight`. Из него формируется `FeedCard`; причина важности остаётся в разборе. UI выводит `effect_title`, `event_summary`, `importance`, источник и дату.
3. При старте диалога создаётся `ChatContext` с фиксированной версией разбора и снимками исходных данных. Материалы банка входят через `context_snapshot.insight.sources` и `bank`. Уточнения пользователя действуют только в диалоге, основной профиль не меняется.

Имена полей — предлагаемый общий словарь команды. `schema_version` — версия контракта, `profile_version` / `insight_version` — версии содержимого. Схема строгая: неизвестные поля отклоняются. При расширении полей обновляйте версию и примеры согласованно.

Для неизменяемых фрагментов используются `source_id` и `fragment_id`; признаки связываются по `feature_ids`. `claims.kind` отличает `source_fact`, `bank_position`, `ai_inference`, `user_data`. Прогноз в источнике остаётся атрибутированным прогнозом, не будущим фактом.

Важность — `high / medium / low`; в ещё не готовой карточке допускается `null`. Уверенность и ограничения не кодируются уровнем важности. `is_demo` помечает демонстрационный объект целиком, `is_fictional` — конкретный источник или событие. Реальное событие и демонстрационный персональный вывод могут сосуществовать.

Позиция банка имеет статусы `found / not_found / outdated / conflicting / unavailable`. Для `found` нужны утверждение и источник типа `bank`. Для `not_found` и `unavailable` содержание отсутствует; причина указывается в `note`. Старая позиция сохраняет дату и период прогноза, противоположные позиции можно представить несколькими источниками и ограничениями.

Численная оценка условна: входы, единицы, период, формула, допущения и происхождение обязательны. Пример +5 млн ₽ — иллюстративный расчёт по вымышленным входам. Значение `false` в уточнении пользователя — известное значение, а не пропуск.

Кнопки, поле ввода, раскрытие аналитики и состояние клавиатуры — поведение интерфейса, не поля бизнес-объектов. `open_insight` определяется по `insight_id`, `pending` — по `message_status`. `retry_of` связывает повторную попытку с исходным сообщением; повторная отправка не должна удваивать пользовательское сообщение. Схемы `Insight` и `ChatContext` описывают загруженное содержимое; ошибки и загрузку без содержимого UI обрабатывает отдельно, формат HTTP-ошибок здесь не выбран.

## Проверка

```sh
python -m pip install -r requirements.txt
python validate.py
```

Команда проверяет валидность схем, все примеры, ссылки на источники/фрагменты/признаки, контекст компании и события и несколько заведомо некорректных объектов. Разрешение `$ref` локальное, сеть при валидации не нужна. Это проверка формы и согласованности данных, не качества аналитики и не подтверждение доступности датасетов.
